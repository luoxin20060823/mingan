## 8. 关键架构决策（不要轻易改动）

1. **单进程 + 进程内 AC 自动机缓存**：避免 Redis 等中间件
2. **L1 同步 + L2 同步 + L3 异步**：L1/L2 用 `asyncio.to_thread` 包装；L3 原生 async
3. **批量请求顺序处理**（不并发跑 L3）：避免 DeepSeek 配额问题；50 条 × 5s 远小于 30s 上限
4. **批量写库单事务**：失败全回滚（满足 R9.8 原子性）
5. **L3 错误降级不抛异常**：让 L1+L2 仍可工作；标记 `flags=["l3_error"]`
6. **词库懒重建**：CRUD 触发 `cache.invalidate()`，下次审核请求时重建（满足 R10.7 一秒生效）

## 9. 关键算法决策（重点关注）

### 9.1 L1 评分公式
```python
LEVEL_BASE = {提示: 0.20, 警告: 0.50, 违规: 0.85}
LEVEL_CAP  = {提示: 0.50, 警告: 0.85, 违规: 1.00}
score = base[top_level] + min(0.05 * (count - 1), cap[top_level] - base[top_level] - 0.01)
```
保证：等级 ≥ 违规 → score ≥ 0.85；命中数单调非递减；不跨档。

### 9.2 L2 评分公式
- 无命中 → 0.0
- 仅符号/空白 → 0.6
- 拼音/谐音/形近 → 0.9

### 9.3 L4 风险阈值映射
- max_score ≥ 0.85 → 违规
- 0.5 ≤ max < 0.85 → 警告
- 0.2 ≤ max < 0.5 → 提示
- max < 0.2 → 合规

### 9.4 L4 类别选择
- 取 score 最高层的类别
- 并列时按 `L3 > L2 > L1` 优先级（理由：LLM 看语义，规则只看表面）

### 9.5 (Risk × Category) → Action 映射表
| Risk | Category | Action |
|---|---|---|
| 合规 | * | pass |
| 提示 | * | pass |
| 警告 | 涉政/暴恐/色情 | manual_review |
| 警告 | 辱骂/广告/其他 | fold |
| 违规 | 涉政/暴恐/色情 | block |
| 违规 | 辱骂/广告/其他 | delete |

## 11. 数据持久化

### 11.1 SQLite 文件
- 路径：`./data/audit.db`（运行时生成）
- 启动配置：`PRAGMA journal_mode=WAL; synchronous=NORMAL;`

### 11.2 表结构
- `audit_records`：13 个字段，4 个索引（created_at、risk_level、category、复合）
- `sensitive_words`：6 个字段，`(word, source)` 唯一约束

### 11.3 启动初始化
- 首次启动（`COUNT(*) sensitive_words == 0`）：从 `./seeds/sensitive_words.csv` 导入 ≥1000 条 builtin 词条
- 非首次：跳过 seed，直接读库
- seed 文件不存在或不足 1000 条 → 启动失败（R16.6）
